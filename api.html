🏗️ Architecture Overview

FreeToolsPDF is a 100% static, client-side web application. There is no backend server, no database, and no server-side processing. Every tool runs entirely within the user's browser.

Key Principle

Your files and data are never uploaded to any server. All processing happens locally using JavaScript, WebAssembly, and browser APIs.

Script Load Order

Scripts are loaded in a specific order at the bottom of each page's <body> to ensure dependencies are available:

1. toast.js       # showToast() — must be first
2. history.js     # localStorage history utilities

4. download.js    # File download utilities
5. Toggle.js      # Dark mode component

🔒 Privacy Model

FreeToolsPDF's privacy is guaranteed by design — there is simply no server to send data to.

Data TypeWhere It GoesUploaded?
PDF filesBrowser memory onlyNever
ImagesBrowser memory / CanvasNever
Calculation resultsBrowser DOM onlyNever
Tool usage historylocalStorageNever
Star ratingslocalStorageNever
Theme preferencelocalStorageNever
Page analyticsMicrosoft Clarity (anonymised)Yes*
* Microsoft Clarity

We use Microsoft Clarity for heatmaps and session recordings. No file content is captured — only user interactions (clicks, scrolls) are recorded.

How PDF processing works

merge-pdf.html — excerpt 
// 1. Lazy-load pdf-lib from CDN (only when needed)
await ScriptLoader.load(
  'https://unpkg.com/pdf-lib@1.17.1/dist/pdf-lib.min.js',
  'PDFLib'
);

// 2. Read files as ArrayBuffers — stays in memory
const buffer = await file.arrayBuffer();
const pdf = await PDFDocument.load(buffer);

// 3. Process and download — never leaves the browser
const bytes = await mergedPdf.save();
const blob = new Blob([bytes], { type: 'application/pdf' });
const url = URL.createObjectURL(blob);
a.href = url; a.download = 'merged.pdf'; a.click();

🔗 Embedding Tools via iframe

Any FreeToolsPDF tool can be embedded in another website using an <iframe>. Because all processing is client-side, the tool works fully within the iframe context.

Free to embed

You're welcome to embed any tool on your blog, school portal, or educational site. Please keep the FreeToolsPDF branding visible for attribution.

Basic Embed

HTML 
<iframe
  src="https://pdftoolsfree.in/tools/attendance-calculator.html"
  width="100%"
  height="600"
  style="border:none;border-radius:12px"
  title="Attendance Calculator — FreeToolsPDF"
  loading="lazy"
></iframe>

Responsive Embed (recommended)

HTML + CSS 
<style>
  .ftpdf-embed-wrap {
    position: relative; padding-bottom: 70%; height: 0; overflow: hidden;
    border-radius: 12px; box-shadow: 0 8px 32px rgba(0,0,0,0.12);
  }
  .ftpdf-embed-wrap iframe {
    position: absolute; top: 0; left: 0; width: 100%; height: 100%; border: none;
  }
</style>

<div class="ftpdf-embed-wrap">
  <iframe
    src="https://pdftoolsfree.in/tools/merge-pdf.html"
    title="Merge PDF — FreeToolsPDF"
    loading="lazy"
  ></iframe>
</div>

📲 PWA & Offline Support

FreeToolsPDF is a Progressive Web App. It can be installed on mobile and desktop devices and works offline for previously visited pages.

Service Worker Strategy

The service worker (sw.js) uses a cache-first with background update (stale-while-revalidate) strategy:

sw.js — fetch handler (simplified) 
self.addEventListener('fetch', (event) => {
  event.respondWith(
    caches.match(event.request).then((cached) => {
      if (cached) {
        // Serve cached immediately
        fetch(event.request).then(res => cache.put(event.request, res)); // update bg
        return cached;
      }
      // Not cached — fetch and cache
      return fetch(event.request).then(res => {
        cache.put(event.request, res.clone());
        return res;
      }).catch(() => caches.match('/offline.html')); // fallback
    })
  );
});

Pre-cached Assets

On install, the service worker pre-caches: index.html, all CSS/JS files, offline.html, and the PWA icons. Individual tool pages are cached on first visit.

FreeToolsPDF uses localStorage exclusively for client-side persistence. Here are all the keys used:

Key PatternValue TypePurpose
suh-theme"light" | "dark"User theme preference
suh-recent-toolsJSON arrayRecently used tool objects (max 4)
suh-rating-{slug}Number 1–5User's star rating per tool
suh-usage-{slug}IntegerSession count per tool
suh-pwa-dismissed"1"PWA install prompt dismissed
cookie-consent"accepted" | "declined"Cookie consent status
Reading data programmatically

You can read any of these keys from the browser console: JSON.parse(localStorage.getItem('suh-recent-tools'))
